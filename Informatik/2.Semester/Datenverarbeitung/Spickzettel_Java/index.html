Threads, Lifecycle & Concurrency

🧠

Ein Thread repräsentiert einen sequentiellen Ausführungsstrang innerhalb eines Prozesses. In Java starten wir Threads am kompaktesten mittels Runnable-Lambda. Bei Zugriffen auf gemeinsame Variablen drohen Race Conditions, die synchronisiert oder atomar gelöst werden müssen.

Regeln & Methoden

2.1 · Thread-Startt.start() erzeugt einen neuen Betriebssystem-Thread und ruft darin run() auf. t.run() führt den Code lediglich sequentiell im aktuellen Thread aus!
2.2 · Warten auf Beendigungt.join() blockiert den aufrufenden Thread, bis t fertig terminiert ist. Wirft InterruptedException.
2.3 · Thread-Zuständet.getState() liefert: NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED.

Synchronisation & Race Conditions

Greifen mehrere Threads ungesichert schreibend auf dieselbe Variable zu (z. B. counter++), kommt es zu Datenverlust, da counter++ aus drei Einzelschritten besteht (Read-Modify-Write).

Lösungsweg 1: public static synchronized void increment() { counter++; } (Monitor sperrt Methode).

Lösungsweg 2 (Lock-frei): AtomicInteger aus java.util.concurrent.atomic.

✎ Klausur-Safe: Threads & Lambda
Thread t1 = new Thread(() -> {
    for (int i = 1; i <= 10; i++) {
        System.out.println(Thread.currentThread().getName() + ": " + i);
    }
}, "Thread-1");

t1.start();
try {
    t1.join(); // IMMER nach start()!
} catch (InterruptedException e) {
    e.printStackTrace();
}
▸ Klausur-Beispiel: Atomarer Zähler (Thread-Safe)
Klassenvariable und nebenläufige Erhöhung
public class Start {
    // ACHTUNG: Auf Klassenebene deklarieren, NICHT lokal in main()!
    private static AtomicInteger safeCounter = new AtomicInteger(0);

    public static void main(String[] args) throws InterruptedException {
        Thread a = new Thread(() -> { for(int i=0; i<1000; i++) safeCounter.incrementAndGet(); });
        Thread b = new Thread(() -> { for(int i=0; i<1000; i++) safeCounter.incrementAndGet(); });
        a.start(); b.start();
        a.join(); b.join();
        System.out.println("Ergebnis: " + safeCounter.get()); // Garantiert 2000
    }
}
Sicherer Endwert ohne Race Conditions: 2.000
Klausurfalle: t1.join() VOR t1.start() aufgerufen → join() kehrt sofort wirkungslos zurück; der Thread läuft nie los oder die Reihenfolge stimmt nicht!

Verschachtelte Klassen (Nested Classes)

🧠

In Java kann eine Klasse in einer anderen definiert werden. Der Hauptunterschied liegt darin, ob die eingebettete Klasse das Schlüsselwort static trägt oder nicht. Dies entscheidet über die Notwendigkeit eines äußeren Objekts.

Klassifikation & Instanzierung

3.1 · Static Nested ClassOuter.StaticNested s = new Outer.StaticNested(); — Benötigt keine Instanz der umschließenden Klasse. Zugriff nur auf statische Outer-Mitglieder.
3.2 · Inner Member ClassOuter o = new Outer(); Outer.Inner i = o.new Inner(); — Benötigt existierende Outer-Instanz. Hat vollen Zugriff auf alle Outer-Instanzvariablen!
3.3 · Java 16+ NeuerungSeit Java 16 dürfen auch nicht-statische innere Member- und Local-Klassen public static Attribute (z. B. Zähler) besitzen.

Typische Klausuraufgabe (LockerSystem)

Gefordert ist meist ein umschließendes System (z. B. LockerSystem) mit einer Liste von inneren Objekten (z. B. Locker). Die innere Klasse erhält einen statischen counter, der bei jeder Erzeugung die eigene id vergibt und hochzählt.

✎ Klausur-Safe: Member Inner Class mit Counter
public class LockerSystem {
    private List lockers = new ArrayList<>();

    public class Locker {
        private int capacity;
        private int lockerId;
        private static int counter = 1; // Java 16+

        public Locker(int cap) {
            this.capacity = cap;
            this.lockerId = counter++;
        }
        @Override
        public String toString() {
            return "Locker #" + lockerId + " (" + capacity + "L)";
        }
    }

    public void addLocker(int cap) {
        lockers.add(new Locker(cap)); // o.new Locker(cap)
    }
    public void display() {
        for (Locker l : lockers) System.out.println(l);
    }
}
Achtung: Aus einer static nested class heraus kann man nicht direkt auf Instanzvariablen der äußeren Klasse zugreifen, es sei denn, man übergibt ein Outer-Objekt als Parameter.

Entwurfsmuster: Java Builder Pattern

🧠

Das Builder Pattern dient der sauberen Erzeugung von unveränderlichen (immutable) Objekten mit vielen optionalen Parametern gleichen Typs. Es verhindert fehleranfällige Riesen-Konstruktoren mit Vertauschungsgefahr.

Strukturprinzip

4.1 · Privater KonstruktorDas eigentliche Objekt besitzt einen privaten Konstruktor, der den Builder entgegennimmt.
4.2 · Statische Innere Builder-KlassePflichtparameter werden im Konstruktor des Builders übergeben; optionale Werte über verkettbare Methoden (Fluent API), die return this; liefern.

Vorteile & Verwendung

Alle Felder der Zielklasse können als final deklariert werden. Der Aufruf liest sich wie natürliche Sprache:

Locker l = new Locker.Builder(1).volume(500).label("Groß").build();
✎ Klausur-Safe: Builder Schablone
public class Locker {
    private final int id;        // Pflicht
    private final int volume;    // Optional
    private final String label;  // Optional

    private Locker(Builder b) {
        this.id = b.id;
        this.volume = b.volume;
        this.label = b.label;
    }

    public static class Builder {
        private int id;
        private int volume = 100;        // Default
        private String label = "Normal"; // Default

        public Builder(int id) { this.id = id; }
        public Builder volume(int v) { this.volume = v; return this; }
        public Builder label(String l) { this.label = l; return this; }
        public Locker build() { return new Locker(this); }
    }
}

🧠

In Java sind Enums keine simplen Integer-Aliase wie in C, sondern vollwertige Spezialklassen, die von java.lang.Enum erben. Sie können eigene Felder, Konstruktoren und Methoden besitzen.

Die Häufigkeitszähler-Falle

Wer map.put(key, map.get(key) + 1); schreibt, erhält beim ersten Auftreten eines Elements unweigerlich eine NullPointerException, weil map.get(key) null liefert und das automatische Unboxing zu int fehlschlägt!

Auch map.replace(key, count++) scheitert, da replace nur existierende Schlüssel aktualisiert, aber keine neuen einfügt.

✎ Klausur-Safe: Null-sichere Häufigkeitszählung
public static Map count(List list) {
    Map map = new HashMap<>();
    for (String item : list) {
        // getOrDefault verhindert NullPointerException!
        map.put(item, map.getOrDefault(item, 0) + 1);
    }
    return map;
}

Generics, Typgrenzen & Wildcards (PECS)

🧠

Generics ermöglichen typsichere Wiederverwendbarkeit. Durch Typgrenzen (Bounds) schränken wir Typparameter ein, z. B. auf vergleichbare Typen. Wildcards (?) steuern die Lese- und Schreibrechte bei Vererbungshierarchien.

Regeln & Prinzipien

7.1 · Bounded Type Parameter<T extends Comparable<T>> garantiert, dass auf Elementen vom Typ T die Methode compareTo() aufgerufen werden darf. Mehrfachgrenzen: <T extends Number & Comparable<T>>.
7.2 · InvarianzList<Integer> ist in Java kein Untertyp von List<Number>! Zuweisung List<Number> l = new ArrayList<Integer>(); führt zu einem Compilerfehler.
7.3 · PECS-RegelProducer Extends, Consumer Super:
• <? extends T>: Lesen (Quelle liefert T). Keine Schreibzugriffe erlaubt (außer null)!
• <? super T>: Schreiben (Ziel nimmt T auf). Sicher Elemente vom Typ T einfügen!
7.4 · Type ErasureGenerics existieren nur zur Compilezeit. Zur Laufzeit wird der Typ durch den Bound (oder Object) ersetzt. Daher ist new T() verboten!

Extremwert-Suche (Min / Max)

Die Klausur verlangt oft eine generische Methode, die je nach Boolean-Flag entweder das kleinste oder das größte Element einer Liste liefert.

res.compareTo(e) liefert eine Zahl > 0, wenn res > e ist, und < 0, wenn res < e ist.

Leerlisten-Check vorab ist Pflicht: if (list == null || list.isEmpty()) return null;
✎ Klausur-Safe: Generische Extremum-Methode
public static > T findExtremum(List list, boolean returnMin) {
    if (list == null || list.isEmpty()) return null; // PFLICHT!
    
    T res = list.getFirst(); // oder list.get(0)
    for (T e : list) {
        if (returnMin) {
            if (res.compareTo(e) > 0) res = e; // neues Minimum
        } else {
            if (res.compareTo(e) < 0) res = e; // neues Maximum
        }
    }
    return res;
}
Klausurfalle: list.getFirst() oder list.get(0) auf einer leeren Liste aufrufen wirft sofort eine NoSuchElementException bzw. IndexOutOfBoundsException!

Stream API (Deklarative Fluent Pipelines)

🧠

Streams erlauben funktionale Massenverarbeitung von Sequenzen ohne explizite Schleifen. Ein Stream speichert keine Daten, sondern verarbeitet Elemente wie auf einem Fließband (Lazy Evaluation).

Operationen im Überblick

9.1 · Intermediäre Operationen (Lazy)Liefern wieder einen Stream: filter(Predicate), map(Function), sorted(), distinct(), skip(n), limit(n).
9.2 · Terminale OperationenSchließen den Stream und liefern ein Ergebnis: count(), collect(Collectors.toList()), forEach(Consumer), min(Comparator), max(Comparator), anyMatch(), allMatch().

Das Einweg-Prinzip (Pipeline-Bruch)

Ein Stream kann nur ein einziges Mal durchlaufen werden. Sobald eine terminale Operation aufgerufen wurde, ist er geschlossen. Wer einen Stream in Variablen zerlegt:

Stream s = list.stream();
s.filter(...);
s.count(); // WIRFT IllegalStateException!

Lösung: Immer als eine einzige, ununterbrochene Kette schreiben.

Filter-Logik: filter(p) behält Elemente, für die p == true gilt. Zum Rausfiltern von "priv" muss negiert werden: .filter(w -> !w.equals("priv")).

✎ Klausur-Safe: Stream Pipeline
String[] rawData = {"2026", "priv", "FirmaA", "FirmaB", "priv", "FirmaA"};

long distinctCount = Arrays.stream(rawData)
    .skip(1)                         // "2026" überspringen
    .filter(w -> !w.equals("priv"))  // "priv" herausfiltern
    .distinct()                      // Duplikate entfernen
    .count();                        // Zählen

System.out.println("Gefunden: " + distinctCount);
Klausurfalle: distinct() vergleicht Objekte über equals() und hashCode(). Wer eigene Klassen im Stream nutzt, MUSS beide Methoden überschrieben haben, sonst funktioniert distinct() nicht!

Reflection API (Introspektion zur Laufzeit)

🧠

Reflection erlaubt es einem Programm, seinen eigenen Aufbau (Klassen, Methoden, Felder, Modifizierer) zur Laufzeit dynamisch zu untersuchen und private Kapselungen auszuhebeln.

Class-Objekt & Modifizierer

12.1 · 3 Wege zum Class-Objekt 1. Literal: MyClass.class | 2. Instanz: obj.getClass() | 3. Dynamisch: Class.forName("de.dhsn.klausur.MyClass")
12.2 · Modifier.toString()Wandelt den Integer-Bitmasken-Wert aus c.getModifiers() in lesbare Strings um (z. B. "public final").

Private Felder manipulieren

Mit c.getDeclaredField("name") erhält man auch private Attribute. Durch setAccessible(true) wird der Zugriffsschutz für diesen Aufruf deaktiviert.

Dynamische Typ-Prüfung: c.isInstance(obj) entspricht obj instanceof C.
✎ Klausur-Safe: Reflection Schablone
// 1. Class & Modifizierer
Class c = Class.forName("java.util.concurrent.ConcurrentHashMap");
System.out.println("Modifier: " + Modifier.toString(c.getModifiers()));

// 2. Methodenanzahl ermitteln
Method[] methods = c.getDeclaredMethods();
System.out.println("Methodenanzahl: " + methods.length);

// 3. Privates Feld lesen & ändern
Field f = c.getDeclaredField("secretField");
f.setAccessible(true); // Umgeht private!
Object val = f.get(myInstance);
f.set(myInstance, "NeuerWert");

XML-Verarbeitung mit DOM & XPath

🧠

Der DOM-Parser baut das gesamte XML-Dokument als Baumstruktur im Arbeitsspeicher auf. Mit XPath können gezielte Knotenmengen über Filterausdrücke (Prädikate) abgefragt werden.

Die 3 XML-Pakete & XPath-Syntax

13.1 · Import-Vorschrift import org.w3c.dom.*; (für Document, Node, NodeList)
import javax.xml.parsers.*; (für DocumentBuilderFactory, DocumentBuilder)
import javax.xml.xpath.*; (für XPath, XPathFactory, XPathConstants)
13.2 · XPath Prädikate"//item[@weight > 100]" filtert alle <item>-Tags, deren Attribut weight größer als 100 ist.

Die NodeList-Schleifen-Falle

NodeList implementiert nicht Iterable! Ein Aufruf wie for (Node n : nodeList) scheitert mit einem Kompilierfehler.

Lösung: Ausschließlich die klassische Index-Schleife mit getLength() und item(i) verwenden.

✎ Klausur-Safe: DOM & XPath
try {
    // 1. DOM Document parsen
    DocumentBuilderFactory dbf = DocumentBuilderFactory.newInstance();
    DocumentBuilder db = dbf.newDocumentBuilder();
    Document doc = db.parse("cargo.xml");

    // 2. XPath auswerten
    XPath xp = XPathFactory.newInstance().newXPath();
    String expr = "//item[@weight > 100]";
    NodeList nl = (NodeList) xp.evaluate(expr, doc, XPathConstants.NODESET);

    // 3. Klassische Index-Schleife!
    for (int i = 0; i < nl.getLength(); i++) {
        Node node = nl.item(i);
        System.out.println(node.getTextContent());
    }
} catch (Exception e) {
    e.printStackTrace();
}
Achtung: VS Code importiert bei Document gerne versehentlich javax.swing.text.Document. Kontrolliere immer, dass org.w3c.dom.Document importiert ist!

Object-Methoden & Logging

🧠

Jede Java-Klasse erbt direkt oder indirekt von java.lang.Object. Für saubere Datenklassen müssen equals() und hashCode() zwingend synchron überschrieben werden. Klonen verlangt bei Referenzen eine tiefe Kopie.

Regeln für equals(), hashCode() & clone()

14.1 · Äquivalenz-VertragWenn a.equals(b) == true, muss zwingend a.hashCode() == b.hashCode() gelten! Umgekehrt dürfen verschiedene Objekte denselben HashCode haben (Kollision).
14.2 · Tiefe Kopie (Deep Clone)Standard-super.clone() kopiert nur primitive Werte und Referenzen (flach). Enthält das Objekt veränderliche Unterobjekte, müssen diese manuell ebenfalls geklont werden.
14.3 · Logging-Leveljava.util.logging.Level-Reihenfolge: SEVERE (Fehler) > WARNING > INFO > CONFIG > FINE > FINER > FINEST.

Musterimplementierung equals & hashCode

@Override
public boolean equals(Object obj) {
    if (this == obj) return true;
    if (obj == null || getClass() != obj.getClass()) return false;
    Clown other = (Clown) obj;
    return id == other.id && Objects.equals(name, other.name);
}

@Override
public int hashCode() {
    return Objects.hash(id, name);
}
✎ Klausur-Safe: Deep Clone & Logging
// Tiefe Kopie:
public class Clown implements Cloneable {
    private Circus circus;
    @Override
    public Object clone() throws CloneNotSupportedException {
        Clown c = (Clown) super.clone();
        c.circus = (Circus) this.circus.clone(); // Deep!
        return c;
    }
}
